# Alfred · 产品愿景

> **元信息** ｜ 状态：现行有效 ｜ 最后更新：2026-08-05 ｜ 范围：产品最上位愿景与分期 ｜ 关联：[ADR-0016](./adr/0016-domain-agnostic-kernel.md)、[ADR 总览](./adr/README.md)

> **Alfred 从「辅助求职的工具」逐步演变为「懂我的个人管家」。**

这一句是本项目的最上位约束。它凌驾于任何单点功能之上——
当某个设计「对求职更省事、但对未来的管家形态是死路」时，**否决它**。

---

## 1. 愿景推论（这些是硬约束，不是愿景口号）

| 愿景 | 架构约束 | 会被它否决的做法 |
|---|---|---|
| 未来要管健康、记账、社交 | 内核（对话 / 记忆 / 实体 / 事件 / 提醒）**必须领域无关**，求职只是第一个领域包 | 把 `interview_round` 这类求职专有字段塞进通用 `event` 表 |
| 「懂我」= 长期累积 | 用户原话**永久留存**；AI 提炼是**可重算的派生物** | 只存 AI 提炼的摘要、丢掉原始语音转写 |
| 「管家」= 主动找我 | 提醒引擎 V1 就要有骨架，不是 V3 的锦上添花 | 做成纯「你问我答」的 RAG 问答机器人 |
| 一个人要用很多年 | 数据可导出、可回滚、可纠错 | 记忆写入无来源追溯、错了只能手动逐条删 |
| 会替我做判断 | 每个结论都要能回答「你凭什么这么说」 | 简历里出现无法溯源到经历/事实的 bullet |

---

## 2. 分期

### V1 · 求职助理（当前）

**核心命题**：把散落在语音、截图、PDF、链接里的求职信息，变成一张能查、能算、能提醒的关系网。

- 岗位捕获（JD 链接 / 截图 / 口述）
- 投递记录（含多模态凭证：投递成功页截图、确认邮件）
- 经历库（口语稿 → 结构化经历 → 按岗位定制的简历 bullet）
- 接触记录（Coffee Chat / 约饭 / 宣讲会 / 线上通话，泛化为 `interaction`）
- 技能匹配（我会什么 × 岗位要什么 → 匹配与缺口）
- 简历生成（Markdown 主信息 + 模板，版本可复用、可溯源）
- 主动提醒（截止日、静默、感谢信、面试备战、技能缺口）

### V2 · 社交 CRM

**核心命题**：人脉不是通讯录，是「关系状态 + 欠的人情 + 该联系的时机」。

- 关系强度与衰减
- Follow-up 到期提醒
- 引荐路径（我认识谁 → 谁认识目标公司的谁）
- 互动历史时间轴

### V3 · 个人管家（本轮已启动扩展，2026-08-04）

**核心命题**：同一个内核，接入新的领域包。本轮已确定首批领域，job 之外新增（数据模型与编排见 [ADR-0021](./adr/0021-domain-graph-packages.md)、[GRAPH.md](./GRAPH.md)）：

- **habit（习惯 Tracker）**：弹吉他、打乒乓球等习惯打卡（`habit_log` 可挂地点）。
- **media（作品 / 书影音）**：书、电影、读后感 / 观后感（`work_item` 可挂地点）。
- **progress（进度 / 项目 / 旅行）**：vlog 进度、项目进度；旅行归入本域（`project.kind='trip'` + `trip_day` 按天挂地点）。
- 内核领域无关（ADR-0016）→ 这些领域包经 Graph 编排（ADR-0018/0019/0021）复用共享 `person` / `location` / `event` / `memory`。

### V4 · 主动代理

**核心命题**：跨域联动，这才是「管家」而不是「多个 App 的合集」。

> 「你下周三下午有终面，但那天你约了体检；而且你上周说过面试前一定要留两小时准备。要我帮你改体检时间吗？」

这个能力**只有在 V1 就把内核做成领域无关**时才可能出现。

## 3. 前端形态演进

1. **第一阶段 · 微信小程序** — 类微信聊天界面，语音 / 文字 / 图片 / 文件双向流转。
   选它是因为：多模态输入门槛最低、能写系统日历（提醒可落地）、分享成本低。
2. **第二阶段 · 个人网页** — 大屏编辑场景：改简历、看投递看板、批量整理经历。
   **不是**为了提醒——网页版的提醒能力反而弱于小程序（见 `design-sessions/2026-08-03-v1-redesign.md` §2.1）。

---

## 4. 不做什么（同样重要）

- **不做通用招聘平台**：Alfred 服务「我」，不服务 HR，不做双边市场。
- **不做自动投递机器人**：投递决策必须由人做，Alfred 只降低摩擦、不代替判断。
- **不做「什么都能聊」的聊天机器人**：闲聊不是能力，是噪声源。无法归入任何领域的输入，落成记忆，不生成人格化回复。
