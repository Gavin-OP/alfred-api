0这份文档在说什么

只讲一件事：东西是怎么从「你随手发一段话/一张截图」变成「库里干净、能查、能复用的数据」的。

你发东西→ 原样存档
永不丢→ AI 拆解→ 你过目确认→ 正式入库→ 随时调用
最关键的一步是「你过目确认」。没有它，截图认错的公司名、AI 瞎编的截止日期，会悄无声息地污染整个库。

已经拍板的三个决策

议题结论为什么
技能库怎么建AI 提议 + 你确认，确认后才进正式词表防止「Excel / Microsoft Excel / 熟练使用 Excel」变成三个技能
个人经历放哪单独建一张表，和笔记彻底分开经历是"简历素材"要反复挑用；笔记是"我的情绪和判断"，用途完全不同
和 Alfred 的对话双方都存，都带时间戳你要的是一条像微信一样能回看的时间线

三个"两层结构"的处理方式不一样

① 职位
不需要新表

大类 = job_family，细分 = title。
职位天然属于某家公司，脱离公司谈"职位大类"没有独立存在的必要。

② 技能
需要新表 · 自引用

大类一条记录，细分一条记录，靠 parent_id 挂上去。
技能要跨公司复用，「所有要 Excel 的岗位」必须能一键查出来。

③ 经历
一层就够

经历表本身是平的，靠挂技能来体现"这段经历证明了什么能力"。

3Agent 对「技能」的定义

整个设计里最需要说死的一点 —— AI 一旦自由发挥，技能库三天就废。

技能 = 一个归一化、去重、可跨岗位复用的「能力标签」，两层结构（大类 → 细分），并且必须能追溯到 JD 里的原句。

技能的四个必填要素

要素说明例子
category 大类粗粒度，用来做导航英语
name 名称具体能力商务写作
evidence_text 证据句JD 里哪句话推出来的"能独立撰写英文邮件与报告"
importance 强度must 硬性 / nice 加分must

AI 抽技能的四步法

  1. 抽取　把 JD 句子压成技能短语：
    "熟练使用 Excel 进行数据透视分析" → Excel
  2. 归一　去掉大小写、标点、修饰词，套同义词表：
    "Microsoft Excel" / "excel" / "EXCEL 技能" → excel
  3. 匹配　拿归一化结果去技能表比对（slug + 别名 + 模糊）：
    命中 → 直接复用（99% 的情况）
  4. 提议　不命中才新建 proposed 技能，等你确认 → approved / merged / rejected
关键约束：proposed 状态的技能不参与任何统计和筛选，它只是候选。即使 AI 提了一堆垃圾，也污染不了你的正式技能库。

什么不算技能

你说的"心理学背景、实习经历"要和能力拆开，否则技能库会混进一堆不是能力的东西。JD 里的要求分三类，全进 position_requirement，用 kind 区分：

kind含义例子挂 skill_id
skill能力英语商务写作、Excel 数据透视、CBT 咨询技术✅ 挂
qualification学历 / 证书 / 专业背景心理学硕士、注册心理师执照❌ 不挂
experience经历 / 年限2 年以上咨询实习经验❌ 不挂
好处：你既能问「所有要 CBT 技术的岗位」，也能问「哪些岗位要求心理学硕士」，两者不混淆。

技能词表初始形态（举例）

心理学 ├── 临床评估 ├── CBT 认知行为疗法 └── 个案报告撰写 英语 ├── 商务写作 └── 会议口语 Microsoft Office ├── Excel 数据处理 └── 商务邮件撰写 研究方法 ├── SPSS 统计分析 └── 文献综述

4工作流一 · 上传 JD

链接 / 截图 / 语音 / 文字，混着发也行。

步骤发生了什么落到哪张表
① 你发东西链接、截图、语音、文字chat_message(user)、ingest_request、attachment
② 原样存档调 AI 之前就先存。AI 全挂了原始输入也在同上
③ 归一成文本链接抓正文 / 截图 OCR / 语音转文字attachment.transcription
④ 选技能（路由）判断这是岗位 / 感想 / coffee chatingest_run(route)
⑤ AI 拆解公司、岗位、日期、投递方式、要求、技能候选、评价ingest_run(extract)
⑥ 预览卡片暂不入库，字段可直接改ingest_run.parsed
⑦ 背景搜集搜公司新闻口碑，只展示不入库不落库
⑧ 你确认改完点确认company/position/position_requirement/note
⑨ Alfred 回话一句话总结 + 待确认技能chat_message(assistant)

5工作流二 · 简历与求职信生成

  1. 你说：给字节的数据分析岗改简历，用经历 1、3、5
  2. Alfred 定位公司 + 岗位（没有就先建）
  3. 从 experience 取出你点名的那几条
  4. 缺口比对：岗位要求 vs 经历带的技能 →「这岗要 SPSS，你选的三条没体现，要不要加经历 4」
  5. 生成 LaTeX 草稿（雏形，还不是最终版）
  6. 你确认 / 让它改
  7. 定稿 → 存 document_version（LaTeX 源码快照）
  8. 编译 PDF → 存文件路径
  9. 抽关键内容建索引，以后能搜「哪份简历写过 SPSS」

关键设计：记住「这版用了哪几条经历」

document_version_experience 新建
document_version_id哪一版简历
experience_id用了哪条经历
order_no在简历里排第几
rendered_bullets这版实际怎么措辞的（同一段经历，投研究岗和投咨询岗写法不一样）
为什么必须有这张表：三个月后收到面试通知，你能一眼看到「当时投这个岗用的是经历 1/3/5，实习那段我强调的是数据分析」，直接照着准备面试。

版本管理规则

不可变
每次定稿 = 一个新版本，老版本永远不改
必填摘要
每版必须有「这版改了什么」，AI 自动生成，你可以改
防灌水
内容没变（checksum 相同）就不建新版本
延后编译
只在你确认后才编译 PDF，草稿阶段不浪费时间

经历表长什么样

字段说明例子
slug唯一标识hku-psy-ra-2025
title显示名香港大学心理系 研究助理
kind类型internship / project / research / volunteer / award
org_name在哪做的香港大学
started_on / ended_on起止2025-06 ~ 2025-09
bullets简历条目候选，可存多种措辞和中英双语["独立完成 40 份个案评估报告", …]
display_order你说的"经历 1、2、3"就是这个1
experience_skill 这张关联表带来一个很爽的能力：Alfred 能反向推荐 —— 「这个岗要 CBT，你的经历 2 里有 CBT，建议加进去」。

7工作流四 · 你和 Alfred 的聊天时间线

为什么要单独一张表：现有的 ingest_request 记的是"处理任务"，不是聊天记录 —— Alfred 的回复只有一句总结，读起来不像对话；而且有些消息（比如"帮我看看这周有什么截止"）根本不产生 ingest 任务，没地方存。
chat_message 新建
sent_at
时间戳，时间线排序靠它
role
user（你发的） / assistant（Alfred 回的）
media_kind
text / voice / image / link / mixed
content_md
显示文本（语音就是转写、图片就是描述）
attachment_ids
语音、图片的原件
ingest_request_id
这条消息触发了哪次处理（可空）
reply_to_id
Alfred 这句在回你的哪句
status
sent / processing / done / failed
和 ingest_request 的分工
chat_messageingest_request
是什么聊天记录，给人看处理任务，给系统用
谁的内容你 + Alfred 双方只有你的输入
读取频率高（每次打开都刷）低（排查问题才看）
数量关系一条 user 消息→ 0 或 1 个任务
有意的冗余：chat_message.content_md 会把语音转写文字冗余存一份，不必每次都去 join 附件表。时间线是读得最频繁的东西，多存一份文本换秒开，划算。

11潜在问题 Brainstorm

先替你踩坑。按风险高低排。

高风险 · 不处理一定出事

① 技能库爆炸
三个月后技能表 400 条，其中 300 条是同义重复
对策　AI 只能提议不能直接入库；proposed 不参与筛选；提供"合并技能"操作，合并时旧说法自动进别名
② 截图 / OCR 认错关键字段
公司名认成"字节眺动"，截止日期认成去年
对策　强制走预览卡片；AI 推算出来的字段（"本周五"→ 具体日期）在卡片上高亮标注
③ 经历和笔记混为一谈
想往简历里加东西时，翻遍笔记也找不到那段实习怎么写的
对策　已定案分表。判断标准一句话 —— 能写进简历的是经历，其余全是笔记
④ 简历版本认不出来
收到面试通知，不知道当初投的是哪版
对策　resume_version_id 硬关联 + 记录用了哪几条经历 + 每版必填改动摘要

中风险 · 会不舒服但不致命

问题对策
⑤ 同岗位重复入库
"数据分析师"和"数据分析实习生"该分开（对的）；"Data Analyst"和"数据分析师"被分开（错的）		指纹先过一遍中英归一表；不确定时在卡片上问你"这是不是和已有的 XX 同一个岗"
⑥ 聊天时间线越滚越长按天分组、分页加载；加 is_pinned 置顶；纯闲聊可标记归档
⑦ 你的评价被塞进 JD 描述里
AI 把"这家听说加班很凶"写进了岗位描述		prompt 已明确"主观评价只进 my_comment"；再加校验 —— 描述字段出现第一人称就打回
⑧ 背景搜集的信息想留下来
搜到"这家去年裁员 30%"，肯定想留		默认不存，卡片上给「存为笔记」按钮，你点了才存成 note(kind=research)

低风险 · 记着就行

⑨ 材料清单没人管
required_documents + 生成 checklist 提醒
⑩ 同岗二次投递
不阻止，但提示"你 3 月投过这个岗"
⑪ 文件越存越多
PDF 本身不大；真占地方的是截图，sha256 去重已解决大半
